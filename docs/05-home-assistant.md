# 5. Home Assistant: от сервера до карточки

**Коротко:** Home Assistant — это сервер умного дома у вас дома (не приложение!). Плату в нём настраивать не нужно — она обнаружится автоматически. Дальше — карточка, автоматизации и (опционально) Алиса.

## Шаг 0. Что такое Home Assistant и зачем сервер

**Home Assistant (HA)** — открытая система умного дома, работающая на вашем сервере (мини-компьютер дома), а не в облаке. Наша плата построена на ESPHome и интегрируется с HA нативно.

Главное заблуждение новичков: *«Люди думают, что Home Assistant — это приложенька на телефон… это сервер, который должен быть у тебя дома»*.

Готовы к серверу — идём дальше. Не готовы — вам хватит [веб-интерфейса](04-web-only.md).

## Шаг 1. Сервер для HA

| Вариант | Комментарий |
|---|---|
| Raspberry Pi 4/5 | Классика; HAOS ставится с флешки за 15 минут (~6–10 тыс. ₽ с питанием и картой) |
| Мини-ПК с маркетплейсов/Авито | Больше мощности, цена плюс-минус такая же, но нужно поискать |
| Старый ноутбук | Отключите экран/сон; следите за шумом |
| Виртуалка/Proxmox/Docker | Для умеющих; есть нюансы с обнаружением mDNS |

Видеоинструкции по установке: канал [«У Павла»](https://www.youtube.com/@upavla) (русскоязычный, для новичков), официальная [документация HA](https://www.home-assistant.io/installation/).

<details>
<summary>Технические детали</summary>
Рекомендуемый путь — HAOS (Home Assistant Operating System): «прошиваете» образ на Raspberry/мини-ПК, дальше всё из браузера. Обновления — кнопкой. Docker — для тех, кто понимает сетевые нюансы (broadcast/mDNS).
</details>

## Шаг 2. Плата обнаружится сама

Убедитесь, что плата [подключена к той же сети](03-first-run.md), что и HA. Интеграция **ESPHome** входит в HA из коробки: устройство появится в «Настройках → Устройства и службы» автоматически (по discovery). Ничего вводить не нужно — ни ключей, ни паролей.

Не появилось? Проверьте, что плата видна в списке клиентов роутера, и перезагрузите страницу интеграций.

## Шаг 3. Сущности платы

| Сущность | Что это |
|---|---|
| `fan.oneair_fan` | Вентилятор: вкл/выкл + скорость 0–100% |
| `switch.oneair_heat` | Нагреватель вкл/выкл (включится только при работающем вентиляторе) |
| `number.oneair_heat_power` | Мощность нагрева 10–100%, шаг 5 |
| `sensor.oneair_heat_current` | Фактическая мощность нагрева сейчас (с учётом защит) |
| `sensor.oneair_temperature` | Температура **на входе** (приточного воздуха с улицы) |
| `sensor.oneair_rpm` | Обороты турбины |
| `binary_sensor.oneair_open` | Открытие крышки/шторки |
| `switch.oneair_led` / `switch.oneair_buzzer` | Подсветка / пищалка |
| `button.oneair_safe_mode` | Безопасный режим (для перепрошивки) |
| `sensor.oneair_ip` / `ssid` / `mac` | Сетевая информация |

> Сущности «климат» (термостат) в HA сами не создадутся — их собирают из fan+heat, см. [рецепты](08-automations.md#термостат).

## Шаг 4. Карточка на дашборд

Проще всего добавить карточку кликами: редактор дашборда → «Добавить карточку» → выбрать устройство бризера. Для любителей YAML — пример карточки:

```yaml
type: entities
title: Бризер
entities:
  - entity: fan.oneair_fan
    name: Вентилятор
  - entity: number.oneair_heat_power
    name: Мощность нагрева
  - entity: switch.oneair_heat
    name: Нагрев
  - entity: sensor.oneair_temperature
    name: Температура притока
  - entity: sensor.oneair_rpm
    name: Обороты
```

Пользователи также собирают красивые карточки [bubble card](https://github.com/Clooos/Bubble-Card) — примеры в [чате](https://t.me/smartintercom/40789).

## Шаг 5. Алиса (Yandex Smart Home)

1. В HA установите интеграцию **Yandex Smart Home** (УДЯ) — [hacs Yandex Smart Home](https://yandex-home.readthedocs.io/) или аналог.
2. Добавьте нужные сущности бризера в список передаваемых.
3. Скажите: «Алиса, включи бризер».

Видео про интеграцию HA в Алису: [youtu.be/iI79eiTZgf8](https://youtu.be/iI79eiTZgf8). Прямой интеграции платы в Алису/Tuya Smart Life — нет.
