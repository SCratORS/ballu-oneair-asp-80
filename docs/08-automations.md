# 8. Рецепты автоматизаций

Готовые сценарии от пользователей. Все делаются в Home Assistant (автоматизации/скрипты) — сама плата даёт сущности: вентилятор, нагрев, мощность, датчики.

> Включение нагрева без вентилятора невозможно на уровне прошивки — в автоматизациях порядок «сначала вентилятор, потом нагрев» соблюдать всё равно хорошая практика.

## Ночной режим

Самый простой сценарий: ночью скорость ниже штатной первой (например, 30–50% — подбирается на слух), днём — выше.

```yaml
# пример автоматизации HA
automation:
  - alias: "Бризер: ночь"
    trigger:
      - platform: time
        at: "23:00:00"
    action:
      # fan.turn_on включает вентилятор и сразу задаёт скорость;
      # fan.set_percentage меняет скорость уже включённого
      - service: fan.turn_on
        target: { entity_id: fan.oneair_fan }
        data: { percentage: 40 }
  - alias: "Бризер: утро"
    trigger:
      - platform: time
        at: "07:30:00"
    action:
      - service: fan.set_percentage
        target: { entity_id: fan.oneair_fan }
        data: { percentage: 65 }
```

> Пример выше — YAML-режим HA (автоматизация «в коде»). То же самое собирается кликами в интерфейсе: **Настройки → Автоматизации → Создать**, триггер «Время», действие «Вызвать службу» (`fan.turn_on` / `fan.set_percentage` с полем «процент») — для новичка это даже проще.

Автор платы про свою семью: *«Я на 30 выставил. Несколько дней тестировал на жене по ночам. Где-то на 37% она сказала — выруби, мешает 😁»*

## Вентиляция по CO₂

Датчик CO₂ в спальне, скорость бризера растёт с концентрацией.

Логика (собирается в HA «Автоматизациями» или в YAML):
- CO₂ < 800 ppm → бризер выключен или минимум
- 800–1200 ppm → 1-я скорость
- \> 1200 ppm → 2-я скорость

Датчики, которые использовали пользователи: EFEKTA iAQ S II (Zigbee), дешёвые CO₂-мониторы с интеграцией в HA. Опыт пользователей: [чат](https://t.me/smartintercom/42497).

## Поддержание температуры притока

Рецепт пользователя Ilia (перенёс штатный датчик температуры за нагреватель — [как](11-advanced.md#перенос-датчика)):

1. Если на улице холоднее, чем «минимально допустимая в комнате» − 15 °C → включаем подогрев.
2. Определяем желаемый диапазон температуры притока (у автора: от «комнатная − 9» до «комнатная − 4»).
3. Показания датчика прогоняем через фильтр 60 с (сенсор обновляется каждые 10 с — для инерционного нагрева это слишком часто).
4. Триггером по фильтру: выше максимума → −шаг мощности, ниже минимума → +шаг; убавлять некуда → выключить.

> «Решение наверняка не идеальное, но работает исправно» — автор рецепта. Обсуждение: [чат](https://t.me/smartintercom/42497).

## <a name="термостат"></a>Термостат (сущность climate)

В HA можно собрать термостат из fan+heat:
- `generic_thermostat` — работает, но **умеет только вкл/выкл** нагрев, не мощность (обсуждение: [чат](https://t.me/smartintercom/41369));
- **PID-регулятор** (встроен в HA) — плавно подбирает мощность под целевую температуру притока; пользователи запускали именно его с перенесённым датчиком: *«выставил целевую T на выходе и пусть сам решит, как её достичь»*.

## Уличная температура + нагрев

Автоматизация «включать подогрев только когда на улице холоднее N» — датчик улицы (Zigbee/Wi-Fi) + условие в автоматизации включения `switch.oneair_heat`. Именно так получают «штатную» логику, но с любыми своими порогами (штатная плата, напомним, вообще запрещала нагрев при плюсе).

## Алиса

Через [Yandex Smart Home](05-home-assistant.md#шаг-5-алиса-yandex-smart-home) сущности бризера доступны голосом: «включи бризер», «выключи нагрев». Скорость голосом регулируется как процент вентилятора.

## Чего делать не стоит

- Не привязывайте критичное к одному источнику данных: если датчик CO₂ отвалился, автоматизация должна деградировать безопасно (например, на минимальную скорость).
