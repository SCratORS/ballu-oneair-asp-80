# 6. Прошивка и обновления

**Коротко:** для большинства случаев готовый бинарник из `bin/` обновляется через веб-интерфейс по воздуху (файл `.ota.bin`). Своя сборка из yaml — когда нужно изменить поведение (свои скорости, Wi-Fi в прошивке, флаг `TK2_mode`).

## Два пути

| | Готовый бинарник | Своя сборка из yaml |
|---|---|---|
| Что нужно | Ничего (веб-браузер) | Home Assistant + ESPHome Builder |
| Когда | обновиться до актуальной прошивки | свои скорости, Wi-Fi/пароль зашиты, `TK2_mode`, эксперименты |
| Минус | **сбрасывается Wi-Fi** после обновления | надо разобраться с Builder'ом |

## <a name="ota"></a>Обновление по воздуху (готовым бинарником)

1. Скачайте [`bin/ballu-oneair-asp-80.ota.bin`](../bin/ballu-oneair-asp-80.ota.bin) (именно `.ota.bin`!).
2. Откройте веб-интерфейс платы → раздел **OTA / обновление** → выберите файл → загрузите.
3. Прошивка обновится, устройство перезагрузится.
4. **Настройки Wi-Fi сбросятся** — это нормально. Дальше как при [первом включении](03-first-run.md): подождать минуту → подключиться к точке доступа (пароль `12345678`) → страница настройки (captive portal — открывается сама при подключении к сети платы) → указать свою сеть → сохранить. Автор: *«После перезагрузки всё автоматом залетит в HA, как и было»*.

> ❗ Файл **без** `.ota` (`ballu-oneair-asp-80.bin`) — полный образ памяти, он шьётся **только программатором**. Залитый через веб, даст ошибку `wrong magic byte`. 

Чтобы Wi-Fi не сбрасывался при обновлениях — соберите прошивку [без зашитых данных Wi-Fi](#своя-сборка) (или со своими): настройки сети сохранятся во flash.

## Своя сборка

### Через ESPHome Builder в Home Assistant

1. Установите HA-дополнение **ESPHome Device Builder** (оно ставится и без HACS, из магазина дополнений HAOS).
2. Возьмите [`ballu-oneair-asp-80.yaml`](../ballu-oneair-asp-80.yaml) из репозитория — «Adopt»/импорт или создайте новое устройство и вставьте содержимое.
3. Заполните секреты Wi-Fi (или уберите строки `!secret`, если хотите настраивать сеть через captive portal — тогда Wi-Fi не будет «зашит» и не сбросится при OTA).
4. Нажмите **Install** → Compile/OTA.

Ошибки компиляции:
- **«Проверь табуляции»** (совет автора) — в yaml отступы делаются пробелами, табы ломают лямбды
- Свежие версии ESPHome иногда ломают старые конфиги: в ноябре 2025 встречалась ошибка `preset.mode == "Low"` (лечится правкой конструкции); актуальный yaml репозитория собирается на свежем ESPHome — если собрались на старом, обновите Builder
- В yaml есть флаг `TK2_mode` с комментарием «До 10.25 - true, после false» — про него ниже

### Несколько бризеров

В актуальной прошивке `name_add_mac_suffix: true` — каждое устройство получает уникальное имя автоматически, конфликты в HA исключены. Ничего делать не нужно.

### Свои значения скоростей

Кнопки на корпусе переключают скорости 30/65/100 — эти значения зашиты в lambda-логике бинарных сенсоров. Изменить их (например, на 40/60/80) можно правкой yaml — [инструкция](11-advanced.md#свои-скорости). Ползунок скорости в вебе/HA и так позволяет ставить любое значение 0–100.

## <a name="tk2"></a>Флаг `TK2_mode`

**Что это.** В `substitutions` yaml:

```yaml
TK2_mode: false # До 10.25 - true, после false
```

Флаг влияет **только на чтение сенсорной кнопки нагревателя** (`inverted:` у `touch_2`). Разные партии микросхем сенсоров (TTP223) на платах дают инверсный сигнал, поэтому:

- платы, выпущенные **до октября 2025** → `TK2_mode: true`
- платы **после октября 2025** → `TK2_mode: false` (значение в репозитории по умолчанию)

**Как проверить, тот ли флаг у вашей платы** (процедура автора):

1. Прошейтесь актуальной прошивкой как есть (там `false`).
2. Попробуйте включить нагрев **с кнопки на корпусе**. Можно даже без вентилятора: раздастся «отказный» тройной писк — значит кнопка читается, всё хорошо.
3. Запустите вентилятор и включите нагрев с кнопки. *«Включился — ок»*.
4. Если реакции на кнопку **нет вообще** — флаг не тот: пересоберите прошивку с другим значением и обновите по OTA.

**Насколько это опасно?** Неверный флаг — это про кнопку, а не про управление нагревателем: *«если флаг не верный, то еспеха будет думать, что кнопка постоянно нажата, и включить не получится. Либо включится, но как-то не так»* (автор). Сам автор ошибался флагом — «ничего страшного не случилось». Но базовое правило сохраняется: после любой перепрошивки [следите за нагревом](02-install.md#warnings) первые минуты.

## Восстановление

- **Кнопка safe mode** (`oneair_safe_mode` в HA/вебе) — переводит плату в режим ожидания прошивки; дальше OTA через веб. Первый инструмент при странных глюках.
- **USB-TTL программатор** — если плата не загружается совсем: [пошаговая инструкция](11-advanced.md#ttl).
